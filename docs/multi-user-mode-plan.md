# 多用户模式改造计划

## 1. 文档目的

本文用于规划“回卷”从单用户本地应用升级为多用户平台的第一阶段改造。目标是：

- 平台初始由管理员创建第一个管理员账户。
- 管理员在后台创建普通用户，暂不开放用户主动注册。
- 普通用户使用账号和密码登录后，只能访问自己的书籍、试卷、复习记录和相关文件。
- 管理员可以管理用户、查看所有用户的书籍和复习内容、维护平台模型配置和提示词，并查看跨用户的模型 Token 用量。
- 数据模型和权限边界为后续组织、多租户、共享书架留下清晰扩展点。

本文同时记录已经落地的改造状态，后续开发以本文的权限边界和阶段验收标准为准。

## 1.1 当前实现状态（2026-08-05）

本轮已经完成第一版多用户基础能力：

- 已完成用户、个人工作空间、成员、Cookie 会话和审计日志模型及数据库迁移。
- 已完成 Argon2 密码哈希、登录失败锁定、登录/退出、当前用户和首次修改密码。
- 已完成管理员用户管理：创建用户、生成一次性临时密码、停用/恢复账户、重置密码。
- 书籍、PDF、原文片段、试卷、出题任务和复习任务已接入工作空间隔离；包括管理员在内，普通业务接口始终只处理当前账号的个人工作空间。
- 模型设置、提示词管理、模型测试和 Token 用量已限制为管理员；Token 记录支持用户归属、按用户筛选和用户汇总。
- 已增加管理员访问统计页面，按天、月、年汇总用户访问次数、登录次数、活跃用户数和访问时长，并支持日期范围及用户筛选。
- 网页端已增加登录、首次改密、账户状态、管理员用户管理、按用户 Token 用量和书籍管理视图；系统管理导航仅管理员可见。
- 管理员通过独立的临时空间查看指定用户书架和书籍详情，管理视图不会与管理员自己的书架混用；内容保持只读，但允许管理员执行书籍下架、恢复和删除。
- 书籍管理支持查看全平台书籍、按用户和上架状态筛选，并将书籍复制到指定用户工作空间；可选择是否复制 PDF 和已解析原文片段，试卷、复习任务、答案和成绩不复制。
- 创建用户和重置密码均只展示一次临时密码；重置操作需要二次确认。系统只保存 Argon2 哈希，管理员不能读取用户原密码。
- 管理员可以通过 `python -m app.cli init-admin` 或安装后的 `huijuan-admin init-admin` 初始化首个账户，初始化过程会回填旧数据归属。

仍待后续阶段完成的内容：管理员查看用户复习答案和结果的完整只读详情、审计日志查询页、PDF/解析文件的按工作空间目录调整，以及公网部署所需的 PostgreSQL、Redis Worker、对象存储、限流和安全加固。

## 2. 当前基线与主要问题

当前版本是单用户 MVP：

- `Book`、`Quiz`、`ReviewTask`、PDF 和原文片段没有用户归属字段，所有 API 默认返回全库数据。
- 模型配置表使用固定的 `default` 单例；提示词模板没有所属用户或工作空间；Token 用量记录没有调用用户。
- API 没有认证、会话和权限依赖，获取对象时也没有所有权校验。
- 网页端没有登录页、当前用户状态、退出登录和未授权页面。
- PDF 保存在统一的本地目录，文件路径没有按用户或数据空间隔离。
- PDF 解析和出题使用 FastAPI 进程内线程；服务重启可以恢复部分任务，但多进程和多实例部署会带来重复执行、资源竞争和任务不可见问题。
- 当前开发默认使用 SQLite。SQLite 可以继续服务本地开发，但不适合作为公网多用户生产数据库。

因此，多用户改造不能只增加一个登录页面，必须同时完成认证、授权、数据迁移、文件隔离、后台任务身份传递和系统设置权限控制。

## 3. 推荐总体设计

### 3.1 认证方式

第一阶段采用基于服务端会话的 Cookie 登录：

- 用户名作为登录标识，要求全局唯一且不区分大小写。
- 密码只保存 Argon2id 哈希，不保存明文或可逆密文。
- 登录成功后签发随机会话令牌；数据库只保存令牌哈希。
- Cookie 使用 `HttpOnly`、`Secure`（生产环境）、`SameSite=Lax` 和过期时间。
- 提供登录、当前用户、退出登录和修改密码接口。
- 认证失败统一返回明确但不泄露账号是否存在的信息。

第一阶段不使用 JWT 作为浏览器主会话。服务端会话更容易实现主动退出、管理员禁用用户、会话撤销和密码重置；未来需要多实例部署时，将会话存储迁移到 Redis 或 PostgreSQL 即可。

### 3.2 用户与角色

第一阶段只定义两个平台角色：

| 角色 | 权限 |
| --- | --- |
| 平台管理员 `admin` | 管理用户、启用/禁用账号、重置密码；查看所有用户的书籍和复习内容，管理书籍上下架和删除；维护平台模型配置和提示词；查看所有用户的 Token 用量；也可以使用自己的个人书架 |
| 普通用户 `user` | 使用自己的书架、PDF、试卷、复习任务和复习记录；不能访问用户管理、模型密钥、提示词和跨用户用量 |

普通用户不允许自行注册。第一阶段也不实现邮箱验证、找回密码、第三方登录和多因素认证；管理员通过后台重置密码。

### 3.3 现在引入隐藏的工作空间边界

推荐现在就引入 `Workspace` 和 `WorkspaceMember`，但第一阶段不在页面上显示工作空间切换：

- 每个新用户自动创建一个私有工作空间，并成为该空间的唯一成员。
- 现有单用户数据迁移到初始管理员的私有工作空间。
- `Book` 作为顶层资源保存 `workspace_id`；PDF、原文片段、试卷、出题任务和复习任务通过书籍关系继承空间边界。
- Token 用量记录同时保存 `workspace_id` 和触发任务的 `user_id`，方便管理员统计。
- 后续组织或租户可以直接对应一个工作空间，通过成员关系实现共享书架、空间管理员和团队权限，而不需要重新给所有内容增加一套隔离逻辑。

这里的工作空间是普通用户之间的数据隔离边界，不等同于平台管理员。平台管理员通过独立管理后台跨空间查看用户的书籍、PDF 原文、试卷、复习答案和结果，并仅通过专用接口管理书籍上下架和删除；普通业务页面仍只处理当前用户自己的工作空间，避免管理员权限意外变成普通接口的全库读写权限。管理员的跨用户管理操作需要写入审计日志。

## 4. 数据模型改造

### 4.1 新增核心表

#### `users`

- `id`
- `username`：唯一、规范化后保存
- `display_name`
- `password_hash`
- `role`：`admin` / `user`
- `status`：`active` / `disabled`
- `must_change_password`
- `last_login_at`
- `created_at`、`updated_at`

建议增加 `failed_login_count`、`locked_until`，用于基础暴力破解防护。

#### `sessions`

- `id`
- `user_id`
- `token_hash`
- `expires_at`
- `revoked_at`
- `last_seen_at`
- `user_agent`、`ip_address`（按隐私政策决定保留周期）
- `created_at`

所有查询按 `token_hash` 和有效期索引；退出登录和禁用用户时立即撤销会话。

#### `workspaces`

- `id`
- `name`
- `workspace_type`：第一阶段为 `personal`
- `status`
- `created_by_user_id`
- `created_at`、`updated_at`

#### `workspace_members`

- `workspace_id`
- `user_id`
- `role`：`owner` / `member`
- `created_at`
- `UniqueConstraint(workspace_id, user_id)`

#### `audit_logs`

管理员创建用户、禁用/启用用户、重置密码、修改模型配置、修改提示词等操作需要保留审计记录：

- `id`
- `actor_user_id`
- `action`
- `target_type`、`target_id`
- `metadata`：只保存非敏感操作信息，不保存密码和 API Key
- `ip_address`、`created_at`

### 4.2 现有表增加归属字段

第一阶段迁移时建议直接给顶层和审计相关数据增加字段：

| 表 | 新字段 | 说明 |
| --- | --- | --- |
| `books` | `workspace_id`、`created_by_user_id` | 书架的核心隔离字段和创建者 |
| `quiz_generation_tasks` | `created_by_user_id` | 后台任务必须知道由哪个用户触发 |
| `model_usage_records` | `workspace_id`、`user_id` | 统计空间和调用者的 Token 用量 |
| `model_configurations` | `scope_type`、`workspace_id`、`updated_by_user_id` | 第一阶段为平台级配置，空间字段预留为空 |
| `prompt_templates` | `scope_type`、`workspace_id`、`updated_by_user_id` | 第一阶段为平台级提示词，空间字段预留为空 |

PDF、原文片段、试卷、题目、复习任务和答案已经通过外键关联到 `books` 或 `quizzes`，查询和写入统一从书籍空间校验，不重复存储用户字段。后续如果需要高频跨表统计，再补充冗余字段和索引。

### 4.3 索引与约束

- `users.username` 唯一索引。
- 所有业务查询使用 `workspace_id +` 业务字段的联合索引，例如 `books(workspace_id, updated_at)`、`review_tasks(book_id, status)`。
- 用户禁用后禁止新建任务，但不删除历史数据。
- 删除用户默认采用软删除或禁用，不直接级联删除其书籍和 PDF。
- 删除工作空间必须是管理员显式操作，并在真正删除前执行二次确认和异步清理。

## 5. 权限边界

### 5.1 认证依赖

后端增加以下依赖函数：

- `get_current_user`：解析 Cookie 会话、检查有效期和用户状态。
- `require_admin`：限制平台管理员接口。
- `require_workspace_member(workspace_id)`：检查用户是否属于空间。
- `get_owned_book(book_id)`：先加载书籍，再校验当前用户的空间成员关系。

不能只在列表接口过滤用户数据，所有详情、上传、修改、删除和任务接口都必须执行同样的对象级授权检查，防止用户通过猜测 UUID 访问他人资源。

### 5.2 接口权限矩阵

| 模块 | 未登录 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 健康检查 | 可访问 | 可访问 | 可访问 |
| 登录 | 可访问 | 可访问 | 可访问 |
| 当前用户/退出登录 | 不可 | 自己 | 自己 |
| 书籍、PDF、试卷、复习任务 | 不可 | 仅自己的工作空间，可管理自己书籍的上下架和删除 | 管理员自己的工作空间可正常使用；通过管理后台查看所有用户空间，并管理任意书籍的上下架和删除 |
| 模型配置 | 不可 | 不可 | 平台管理员 |
| 提示词管理 | 不可 | 不可 | 平台管理员 |
| Token 用量 | 不可 | 不可 | 全平台，支持按用户/空间/任务类型筛选、汇总和明细查看 |
| 用户管理 | 不可 | 不可 | 平台管理员 |
| 审计日志 | 不可 | 不可 | 平台管理员 |

管理员跨用户查看时不能代用户修改书籍内容、上传 PDF、出题或答题；书籍上下架、恢复和删除属于明确授权的后台生命周期操作，必须通过管理员接口执行并记录审计日志。

## 6. 认证与账号功能设计

### 6.1 登录流程

1. 用户访问任意业务页面。
2. 前端调用 `/api/auth/me` 检查当前会话。
3. 未登录时跳转 `/login`，保存原始目标地址。
4. 用户提交用户名和密码到 `/api/auth/login`。
5. 后端验证密码、账号状态和登录限制，创建会话 Cookie。
6. 前端加载用户信息和可见导航，跳转回原目标地址。
7. `must_change_password=true` 时只能进入修改密码页面，修改成功后再访问业务页面。

### 6.2 管理员创建用户

后台新增“用户管理”页面，至少支持：

- 用户列表：用户名、显示名称、角色、状态、创建时间、最后登录时间。
- 创建普通用户：用户名、显示名称、临时密码。
- 创建成功后只展示一次临时密码，页面不再次读取明文。
- 启用/禁用用户。
- 管理员重置密码，生成或设置新的临时密码。
- 查看用户会话数量并撤销全部会话。
- 从用户列表进入用户内容页，查看该用户的书架、PDF 文件预览/下载、解析状态、原文片段、试卷、复习任务、答案和结果，并管理书籍上下架和删除。
- 管理员查看用户内容时显示当前用户和工作空间上下文，避免误把管理视图当成管理员自己的书架。
- 用户原密码不能查看：数据库只保存不可逆密码哈希；管理员重置后只能查看本次新生成的临时密码，关闭凭据弹窗后不能再次读取。

创建用户时自动创建个人工作空间。管理员不能创建第二个平台管理员；平台管理员的增加应通过受控命令或明确的高权限操作完成。

### 6.3 密码与会话策略

- 密码最小长度建议 10 位，要求至少包含字母和数字；不做过度复杂的强制规则。
- 普通用户首次登录必须修改临时密码。
- 会话默认 7 天有效，活跃时可滑动续期；修改密码、禁用账号和管理员撤销会话时立即失效。
- 登录失败返回统一错误；同一账号连续失败达到阈值后短暂锁定。
- 暂不做“忘记密码”，由管理员重置。
- 生产环境必须启用 HTTPS、Secure Cookie 和反向代理层的登录限流。

## 7. 系统设置的归属设计

### 7.1 模型配置

第一阶段采用平台级模型配置：

- 由管理员维护接口地址、模型名称、超时、温度和 API Key。
- 所有普通用户的出题和问答评分使用这套配置。
- 普通用户看不到 API Key、完整模型连接测试结果和配置页面。
- 管理员测试连接时需要在 Token 用量中记录调用者和测试结果。
- 保存 API Key 时继续只返回“已配置”和掩码，不允许通过读取接口拿到明文。

未来如果要支持用户自带模型，再增加 `user` 或 `workspace` 级配置，并规定优先级：`用户覆盖 -> 工作空间配置 -> 平台默认`。当前不提前开放这个复杂度。

### 7.2 提示词管理

第一阶段提示词仍由管理员维护平台级版本：

- 普通用户只消费当前生效版本，不可修改。
- 出题任务创建时记录实际使用的提示词版本，避免管理员更新模板后无法追溯历史任务。
- 未来支持空间级提示词覆盖时，沿用“平台默认 -> 工作空间覆盖”的解析顺序，并保留版本审计。

### 7.3 Token 用量

管理员 Token 页面增加：

- 用户维度汇总表：用户名、显示名称、工作空间、任务数、调用次数、输入 Token、输出 Token、总 Token、失败次数。
- 按用户、工作空间、任务类型、时间范围筛选；默认按总 Token 或最近调用时间排序。
- 点击某个用户进入该用户的任务明细，再按阶段展开出题、格式修正、问答评分和连接测试调用。
- 展示输入、输出、总 Token、调用次数、失败次数和未报告用量。
- 任务展开后仍按阶段显示出题、格式修正、问答评分和连接测试。
- 每条用量记录保存触发用户和工作空间；管理员执行模型连接测试时也必须归属到管理员账号。
- 普通用户第一阶段不展示平台总量；未来可以只展示自己的用量摘要。

### 7.4 访问统计

访问统计作为平台级系统管理能力，由管理员统一查看，普通用户不能访问。第一版采用“访问会话”作为统计口径：登录成功建立会话，同一会话 30 分钟内的连续活动计为一次访问；页面可见时每 60 秒发送心跳维持活动状态，心跳不增加访问次数。主动退出和会话撤销会关闭记录，异常退出按最后活动时间后 2 分钟估算结束。

管理员页面 `/settings/access-statistics` 提供三种互斥的汇总粒度：

| 粒度 | 默认范围 | 用途 |
| --- | --- | --- |
| 按天 | 从首条真实访问所在日期起，最多最近 30 天 | 观察日常访问、工作日与周末差异 |
| 按月 | 从首条真实访问所在月份起，最多最近 12 个月 | 观察月度活跃趋势 |
| 按年 | 从首条真实访问所在年份起，最多最近 5 年 | 观察年度用户规模和长期使用趋势 |

每种粒度都从首条真实访问记录对应的时间段开始返回连续时间桶，不展示统计功能启用前没有真实数据的历史；进入真实采集范围后，即使某天、某月或某年没有访问也保留 0 值，便于表格比较和后续图表化。管理员可以按北京时间日期范围查询，也可以按用户筛选；页面同时展示总览指标、时间段汇总表和用户汇总表。数据库统一保存 UTC，跨午夜访问的次数归开始日期，时长拆分到实际涉及的时间段。

接口约定为 `GET /api/settings/access-statistics` 和 `POST /api/auth/activity`。后续引入租户后，访问记录继续保存 `workspace_id` 和 `user_id`，统计接口在平台管理员范围之下增加租户、工作空间和用户权限过滤，不改变页面的三种基础粒度。

## 8. 文件与后台任务隔离

### 8.1 文件存储

本地开发阶段继续使用文件系统，但目录改为：

```text
data/uploads/{workspace_id}/{book_id}/{pdf_id}.pdf
data/parsed/{workspace_id}/{book_id}/{pdf_id}/...
```

文件下载和删除只能通过后端根据数据库记录访问，不能把本地绝对路径暴露给前端。

公网部署前建议切换到 S3/MinIO 等对象存储，数据库只保存对象 Key；对象 Key 必须包含工作空间和书籍标识，并通过后端鉴权后生成短时下载地址。

### 8.2 异步任务

第一阶段先修正当前线程模型的身份边界：

- 任务表保存 `created_by_user_id` 和 `workspace_id`。
- 后台线程只接收任务 ID，从数据库读取任务归属，不依赖请求线程里的用户对象。
- PDF 解析、手动出题、预生成和模型调用均在服务内部重新建立数据库会话。
- 任务状态接口只返回当前用户有权限查看的任务。

在真正开放公网并发前，替换为独立 Worker：

- Redis 作为队列和短期状态存储。
- Celery 或同类成熟任务队列执行 PDF 解析和模型任务。
- Web API 只负责创建任务、查询状态和取消任务。
- Worker 通过任务 ID读取归属和权限，不接受前端传入的任意用户 ID。
- 增加每用户并发数、文件容量和每日模型调用预算，防止单个用户耗尽资源。

## 9. 前端改造

### 9.1 新增页面

- `/login`：用户名、密码、登录错误、会话过期提示。
- `/change-password`：首次登录或管理员重置后强制修改密码。
- `/admin/users`：管理员用户管理。
- `/admin/users/{user_id}/space`：管理员临时查看某个用户的工作空间和书架，并进入独立书籍管理详情。
- `/admin/audit-logs`：管理员操作审计，可与 Token 用量合并为后台管理模块。
- `/settings/access-statistics`：管理员按天、月、年查看用户访问汇总，并按日期范围或用户筛选。

当前 `/settings/model`、`/settings/prompts`、`/settings/token-usage` 和 `/settings/access-statistics` 保留路径，但只对管理员显示和开放。

### 9.2 应用壳与数据请求

- `AppShell` 增加当前用户区域、用户名、角色和退出登录按钮。
- 系统管理导航仅管理员可见。
- API 请求统一带 `credentials: "include"`，遇到 `401` 清理前端用户状态并跳转登录页。
- 增加 `AuthProvider` 或等价的用户状态加载机制，避免每个页面各自实现登录判断。
- 页面加载时区分 `401`、`403` 和普通业务错误：未登录跳转、无权限显示禁止访问、其他错误按原有方式提示。
- 服务端 API 永远是最终权限判断，前端隐藏导航只用于用户体验，不能作为安全边界。
- 管理员内容查看使用独立的管理页面和查询接口，不复用普通用户书架接口返回全库数据；上下架和删除使用单独的管理员操作接口。

### 9.3 账号体验

- 登录成功后保留用户最后访问页面。
- 退出登录后撤销当前会话并返回登录页。
- 管理员禁用用户后，下一次 API 请求立即失效；前端显示账号已被停用。
- 普通用户不显示任何模型密钥、系统提示词和其他用户数据。

## 10. 单用户数据迁移方案

迁移必须保证现有本地数据仍属于最初的管理员：

1. 部署迁移创建用户、会话、工作空间和成员表。
2. 通过一次性 CLI 创建管理员，密码从环境变量或交互输入获得，不写入迁移脚本。
3. 创建管理员的个人工作空间。
4. 给现有所有 `books` 回填管理员的 `workspace_id` 和 `created_by_user_id`。
5. 给现有出题任务和 Token 用量回填管理员的 `user_id`/`workspace_id`。
6. 将现有模型配置和提示词标记为平台级配置，保留原有版本和测试记录。
7. 完成数据校验后再将归属字段改为非空，并建立索引。
8. 迁移完成后关闭 `SEED_DEMO_DATA` 生产配置，避免服务启动重复写入演示数据。

迁移脚本必须支持重复执行检查，并在生产升级前自动备份数据库。SQLite 数据量较小时可以原地迁移；数据量大或准备切换 PostgreSQL 时，应使用导出、转换、校验、切换的独立流程。

## 11. API 设计草案

### 11.1 认证接口

```text
POST /api/auth/login
GET  /api/auth/me
POST /api/auth/logout
POST /api/auth/change-password
```

### 11.2 管理员用户接口

```text
GET    /api/admin/users
POST   /api/admin/users
PATCH  /api/admin/users/{user_id}
POST   /api/admin/users/{user_id}/reset-password
POST   /api/admin/users/{user_id}/sessions/revoke
GET    /api/admin/users/{user_id}/books
GET    /api/admin/users/{user_id}/books/{book_id}
GET    /api/admin/users/{user_id}/books/{book_id}/chunks
GET    /api/admin/users/{user_id}/quizzes/{quiz_id}
GET    /api/admin/users/{user_id}/reviews
GET    /api/admin/users/{user_id}/reviews/{review_id}
```

用户创建、状态修改、密码重置和会话撤销必须写入审计日志。
管理员查看普通用户书籍、PDF、试卷和复习结果也写入审计日志；日志只记录操作者、目标用户/资源、动作和时间，不记录正文内容。

### 11.3 现有接口改造规则

所有现有业务接口保留原有 URL，增加认证依赖和空间过滤，不通过 URL 暴露用户标识：

- `GET/POST/PATCH/DELETE /api/books...`：只操作当前用户工作空间的书籍。
- PDF、原文片段、试卷、出题任务和复习任务：沿父级书籍校验空间。
- `GET /api/reviews`：只返回当前空间的复习记录。
- `GET /api/admin/books?owner_id={user_id}`、`GET /api/admin/books/{book_id}` 和原文片段子接口：仅管理员可访问，用于独立管理视图。
- `POST /api/admin/books/{book_id}/unlist`、`POST /api/admin/books/{book_id}/restore` 和 `DELETE /api/admin/books/{book_id}`：仅管理员可访问，用于管理任意用户书籍的生命周期并记录审计日志。
- `POST /api/admin/books/{book_id}/copy`：仅管理员可访问，将书籍资料复制到指定用户工作空间；试卷和复习数据不在复制范围内。
- `/api/settings/model`、`/api/settings/prompts`：仅管理员。
- `/api/settings/token-usage`：仅管理员，必须支持按 `user_id`、工作空间、任务类型和时间范围筛选，并返回用户维度汇总和阶段明细。

## 12. 部署与基础设施调整

### 12.1 开发和测试

- SQLite 继续作为单机开发和自动化测试数据库。
- 增加多用户测试 fixture，每个测试创建独立用户和工作空间。
- 增加跨用户访问测试：用户 A 不能读取、修改、删除用户 B 的书籍、PDF、试卷和复习记录。

### 12.2 公网生产

正式开放给多个用户前，以下能力是必选项；当前多用户开发阶段暂不实施：

- SQLite -> PostgreSQL，解决并发写入、事务和索引能力问题。
- 进程内线程 -> Redis + 独立 Worker，避免多实例重复任务。
- 本地文件目录 -> S3/MinIO，对象存储和备份更可靠。
- 直接端口访问 -> Nginx/Caddy 反向代理，统一 HTTPS、Cookie 域名、请求体限制和限流。
- 增加结构化日志、错误监控、数据库备份恢复演练和任务失败告警。

- 增加跨用户隔离测试和迁移回滚说明。

### 阶段三：管理员后台（用户与书籍管理已完成）

交付标准：管理员可以完整管理普通用户，在管理视图中查看任意用户内容并管理书籍生命周期；普通用户不能看到或调用后台管理接口，也不能操作其他工作空间的书籍。

### 阶段五：公网并发准备

交付标准：可以在多进程/多实例部署下稳定处理多个用户同时上传、解析、出题和答题。

## 14. 验收标准

### 账号与权限

- 初始管理员只能通过初始化流程创建，密码不进入 Git 和迁移脚本。
- 管理员创建的普通用户可以登录，首次登录被要求改密码。
- 未登录访问业务页跳转登录，业务 API 返回 `401`。
- 普通用户访问管理员接口返回 `403`。
- 禁用用户无法继续使用已建立的会话。

### 数据隔离

- 用户 A 看不到用户 B 的书籍列表、搜索结果、PDF、试卷、复习记录和任务进度。
- 用户 A 使用用户 B 的资源 ID 访问详情、上传、删除和提交接口时均失败。
- 后台任务完成后只更新原归属用户的资源。
- 文件路径、对象 Key 和下载接口都不会跨空间访问。

### 管理与审计

- 管理员可以创建、禁用、启用、重置普通用户密码和撤销会话。
- 模型 API Key 对普通用户不可见，管理员读取接口也只返回配置状态或掩码。
- Token 用量可以按用户和任务阶段统计。
- 管理员关键操作可追溯到操作者和时间。

### 回归

- 现有单用户数据升级后归属初始管理员且内容不丢失。
- 现有 PDF 原文、模型出题、复习评分和文档功能不因加认证而失效。
- 认证、越权、会话过期、任务隔离和迁移均有自动化测试。

## 15. 已确认的产品决策

以下决策作为后续开发基线：

1. 每个用户拥有一个私有工作空间，普通用户之间的数据隔离；管理员可以在后台跨工作空间查看所有用户的书籍、PDF、试卷、复习任务、答案和结果，并管理书籍上下架和删除。
2. 当前单用户模式下的模型设置、提示词管理和 Token 用量等系统管理功能继续由管理员统一维护，普通用户只使用平台配置。
3. 新用户临时密码由管理员创建后线下交付，用户首次登录必须修改密码；当前不接入邮件和用户主动注册。
4. PostgreSQL、Redis 和对象存储作为正式公网开放前的必选基础设施，当前多用户开发阶段继续使用 SQLite、进程内任务和本地文件进行迭代验证。
5. 管理员 Token 用量页面必须区分用户统计：支持按用户筛选、按用户汇总、查看用户任务明细，并继续展开到各模型调用阶段。
6. 管理员自己的书架和普通业务接口只处理管理员个人工作空间；跨用户查看和书籍生命周期操作必须进入独立管理视图。
7. 管理员可以复制书籍资料到指定用户，PDF 和原文片段由管理员选择；试卷、复习任务、答案和成绩不复制。
8. 用户密码只保存不可逆哈希；管理员不能查看原密码，只能二次确认后重置并查看一次新临时密码。
