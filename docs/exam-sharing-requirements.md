# 考试分享功能需求与实现说明 v1.1

> 文档状态：已确认并完成第一版开发
>
> 适用范围：多用户模式第一版
>
> 完成日期：2026-08-06
>
> 文档目的：记录“将现有复习试卷通过链接分享给登录或未登录参与者答题”的产品范围、权限边界、实现结果和验收标准。

## 0. 实现结论

第一版已完成以下闭环：

- 用户可以从自己书籍的已完成试卷创建多个独立考试活动并复制分享链接。
- 登录用户自动使用账号身份，未登录参与者填写答题名称后可以开始、继续、提前交卷和查看结果。
- 管理员可以配置微信开放平台网站应用；参与者完成微信授权后以稳定微信身份答题，页面和管理端展示昵称、头像及“微信认证”标识。
- 微信认证可按平台策略设为公开考试必选项；平台账号身份优先于微信身份，未强制认证时继续保留匿名入口。
- 客观题由后端确定性评分，问答题使用当前平台模型配置异步评分；失败答卷可由分享者或管理员重新评分。
- 分享者在“考试管理”查看活动状态、创建日期范围、答题统计和逐题详情；管理员在“系统管理 / 考试管理”查看全平台数据并按用户、状态、日期筛选。
- 公开答题接口在交卷前不返回答案、解析、评分要点和 PDF 来源，交卷后仍不返回 PDF 文件名、页码和原文摘录。
- 匿名答题访问凭据仅在创建时返回，服务端只保存哈希；活动、答卷和 Token 用量均保留用户及工作空间归属。
- 原试卷或书籍删除后活动自动失效，但试卷快照、历史答卷和成绩继续保留。

当前实现继续使用 SQLite、进程内后台线程和本地文件，适合现阶段开发验证。正式公网多人运行前仍必须完成 HTTPS、公开接口限流、PostgreSQL、Redis Worker、对象存储、备份与监控，详见第 11 节。

## 1. 背景与目标

当前系统中的复习试卷只供书籍所属用户在自己的工作空间内反复复习。新增考试分享能力后，用户可以选择一套已经生成完成的试卷，创建一个独立的考试活动并获得分享链接。其他人打开链接后即可参加答题，不要求必须拥有平台账号。

本功能的主要目标：

1. 降低参与门槛，让未登录用户也可以直接参加考试。
2. 让分享者能够集中查看自己发起的考试、分享链接、参与情况和答题结果。
3. 保持现有个人复习数据与外部考试数据相互独立，避免统计和权限混乱。
4. 管理员能够查看全平台用户创建的考试及其答题情况。
5. 支持按考试活动设置有效期，并为限制参与范围、批量导出成绩和多人考试统计保留扩展空间。

## 2. 与现有功能的关系

### 2.1 复习试卷

复习试卷仍是题目、答案、解析、评分要点和来源信息的原始载体。只有已经生成完成且未删除的试卷可以创建考试分享。

### 2.2 考试活动

一次“分享”在系统中定义为一个独立的考试活动：

- 一个考试活动对应一套复习试卷和一个分享链接。
- 同一套试卷可以创建多个考试活动，用于区分不同参与群体或不同时间段。
- 考试活动保存创建时的只读试卷快照，后续原试卷发生变化或被删除时，已有答题结果仍可追溯。
- 考试活动拥有独立的名称、状态、链接代码、分享者、创建时间和统计数据。

### 2.3 答题记录

参与者每次开始考试后创建一份答题记录。答题记录与现有个人 `ReviewTask` 分开保存，不计入参与者或分享者的个人复习次数、复习得分和复习历史。

### 2.4 范围说明

本功能属于“持有链接即可参加”的受控考试分享，不等同于公开题库、社区广场、题目搜索、排行榜或书籍内容公开分发。上述公开社区能力仍不在本期范围内。

## 3. 用户角色

### 3.1 分享者

已登录的普通用户或管理员。可以为自己工作空间中的试卷创建考试活动，管理自己创建的活动并查看参与者答题结果。

### 3.2 登录参与者

已经登录平台、通过有效分享链接参加考试的用户。系统直接读取其当前账号身份，不再要求填写名称。

### 3.3 匿名参与者

未登录平台、通过有效分享链接参加考试的用户。开始答题前必须填写“答题名称”。该名称仅用于本次考试结果识别，不会创建平台账号。

### 3.4 微信认证参与者

未登录平台但通过微信开放平台网站应用完成授权的参与者。系统保存微信 `openid`，在可获得时同时保存 `unionid`，以稳定标识关联同一考试中的历史答卷；管理端只展示昵称、头像和认证标识，不返回 `openid` 或 `unionid`。微信认证证明参与者控制该微信账号，不等同于实名身份认证。

### 3.5 管理员

除管理自己创建的考试外，可以在系统管理中查看全平台所有用户分享的考试、参与情况和答题结果。管理员跨用户查看行为应写入审计日志。

## 4. 核心产品规则

### 4.1 分享链接

- 分享链接建议使用 `/exams/{share_code}`。
- `share_code` 必须使用高强度随机值，不能使用连续数字、试卷 ID 或其他可枚举信息。
- 分享者可以复制链接、查看链接状态、停止分享和恢复分享。
- 链接默认长期有效，分享者在创建时可指定北京时间截止时间，并可在考试管理中修改或清除有效期。
- 到期后不允许开始新答题，也不允许未提交答卷继续作答或交卷；页面统一提示“你来晚了，考试已经结束”。
- 到期不删除答卷，已经提交、评分中或评分完成的参与者仍可按原身份查看历史结果。
- 停止分享后不能创建新的答题记录；已经开始的答题记录允许继续提交，已有结果继续保留。
- 同一套试卷可以创建多个链接，各链接的参与者和统计结果相互独立。

### 4.2 参与者身份

- 登录参与者自动使用账号显示名称，并同时保存用户 ID 和名称快照，避免以后修改名称影响历史结果。
- 身份识别优先级为平台账号、微信身份、匿名凭据；同一微信账号对同一考试活动只保留一份答卷。
- 微信昵称允许重复，防重复与历史找回使用 `openid/unionid`，不能使用昵称判定身份。
- 匿名参与者必须填写答题名称，建议限制为去除首尾空格后 2 至 50 个字符。
- 管理页面需要明确标识“平台用户”“微信认证”或“匿名参与者”，不能只根据名称判断身份。
- 开始考试前应提示参与者：身份名称、头像、答案、成绩、提交时间、终端和 IP 将对考试分享者可见。

### 4.3 重复答题

第一版建议采用以下默认规则：

- 同一登录账号对同一个考试活动只能产生一份有效答题记录。
- 匿名参与者按当前浏览器中的匿名答题凭据限制为一份有效记录。
- 未提交时可以继续原答题记录，不能重复创建新记录。
- 已提交后只展示结果，不提供重新答题入口。
- 匿名模式无法严格阻止参与者更换浏览器、清除浏览器数据或更换名称后再次答题，页面和管理端不能把该限制表述为严格实名防重复。

后续可以为考试活动增加“允许重复答题”和“保留最高分/最后一次成绩”的可配置策略，本期暂不开放。

### 4.4 试卷快照与删除

- 创建考试活动时保存完整只读快照，至少包括题目顺序、题干、选项、正确答案、解析、问答参考答案、评分要点、分值、难度和来源模式。
- 原试卷删除时，系统自动停止基于该试卷创建的所有活动，不能再开始新答题。
- 已有活动、快照、答题记录和成绩继续保留，保证历史结果可查看。
- 删除考试活动时第一版建议采用逻辑删除或归档，不物理清理答题记录；页面操作文案使用“删除活动”时必须明确已有成绩仍由管理员保留，或者仅提供“停止分享”以避免误解。

## 5. 功能流程

### 5.1 创建考试分享

1. 用户进入书籍详情页的试卷列表。
2. 在目标试卷上点击“分享考试”。
3. 系统弹出创建窗口，展示试卷名称、题目构成、难度和预计用时。
4. 用户填写考试活动名称；默认值建议为“书名 + 试卷名称”。
5. 用户确认后，系统创建考试活动、保存试卷快照并生成分享链接。
6. 创建成功后弹窗展示完整链接，并提供复制按钮和“进入考试管理”入口。

以下情况不能创建分享：

- 试卷仍在生成或生成失败。
- 试卷没有题目或题目数据不完整。
- 书籍已下架。
- 试卷或书籍不属于当前用户工作空间。

### 5.2 参加公开考试

1. 参与者打开分享链接。
2. 系统检查活动是否存在、是否启用、是否过期以及试卷快照是否可用。
3. 登录用户看到当前平台身份；微信用户完成扫码授权后显示昵称和头像；管理员启用强制微信认证时不再提供匿名名称入口。
4. 参与者点击“开始答题”，系统创建答题记录并开始计时。
5. 参与者完成单选题、多选题和问答题，可以在题目之间切换。
6. 参与者可以正常交卷，也可以提前交卷；未作答题目统一按 0 分处理。
7. 客观题立即评分，问答题进入异步 AI 评分。
8. 评分完成后进入结果页；评分尚未完成时显示明确进度并自动刷新。

### 5.3 恢复匿名答题

- 创建匿名答题记录后，服务端返回一次随机的答题访问凭据。
- 前端将凭据保存在当前浏览器会话中，后续请求携带该凭据。
- 服务端只保存凭据哈希，不能仅凭可猜测的答题记录 ID 访问答案或成绩。
- 页面刷新后可以恢复未提交答卷或查看已完成结果。
- 匿名访问凭据保存在当前浏览器的本地存储中；更换设备、浏览器或主动清除浏览器数据后仍可能无法恢复，微信认证参与者则按稳定微信身份跨设备找回。

### 5.4 微信身份找回

- 微信登录使用开放平台网站应用 QR OAuth，授权状态为一次性随机值并绑定发起授权的浏览器 Cookie，防止状态重放和跨浏览器劫持。
- 授权成功后服务端创建只保存令牌哈希的 `HttpOnly` 微信会话 Cookie，前端不能读取会话令牌。
- 参与者再次打开同一考试链接时，系统按微信身份查询原答卷，并提供继续答题或查看历史答卷入口。
- 微信接口异常、授权状态过期或浏览器不匹配时必须明确报错，不创建参与者或答卷。

### 5.5 评分与异常处理

- 单选题和多选题由后端确定性评分。
- 问答题复用平台现有的 AI 评分配置、提示词和评分规则。
- 提交后的状态至少包括：`评分中`、`已完成`、`评分失败`。
- AI 评分失败时保留全部答案和已完成的客观题成绩，不允许参与者重复提交覆盖答案。
- 分享者和管理员可以在管理详情中查看失败原因并触发“重新评分”。
- AI 评分产生的 Token 用量归属考试分享者及其工作空间，并关联考试活动和答题记录，便于管理员按用户追踪成本。
- 评分完成后按答卷中的知识点聚合实际得分；知识点得分率低于 60% 时标记为薄弱知识点，并根据题型、缺失评分要点和正确选项生成可解释的深入学习方向。该分析由确定性规则完成，不额外调用模型，历史答卷也可直接计算。

## 6. 页面与交互需求

### 6.1 试卷列表入口

书籍详情页的每套可用试卷增加“分享考试”操作。已经创建过分享活动不影响再次创建新的活动。

### 6.2 考试管理

普通导航增加“考试管理”，所有已登录用户可见，默认只展示当前用户创建的考试活动。

列表至少展示：

- 考试活动名称。
- 对应书名和试卷名称。
- 活动状态：分享中、已停止、已过期、原试卷已删除。
- 分享链接及复制操作。
- 开始答题人数、已提交人数、评分中人数和评分失败人数。
- 完成率、平均分、最高分。
- 创建时间和最近提交时间。
- 查看详情、停止分享、恢复分享等操作。

支持按活动名称、书名和试卷名称搜索，并按活动状态和创建时间筛选。

### 6.3 考试详情

考试详情页分为“活动概况”和“答题记录”。答题记录至少展示：

- 答题名称或登录用户名称。
- 身份类型：平台用户、微信认证或匿名参与者；微信身份同时展示头像。
- 答题状态。
- 开始时间、提交时间和答题用时。
- 实际得分、满分和得分率。
- 逐题答案、逐题得分和评分反馈。
- 问答题评分失败原因及重新评分入口。
- 已完成答卷的实际得分柱状图；纵轴统一为 0-100 分，评分中和评分失败的答卷不参与统计。
- 每位参与者的薄弱知识点、知识点得分率、待补充内容和建议深入掌握方向；未发现低于 60% 的知识点时给出继续巩固建议。
- 开始答题时的终端类型、IP 和浏览器 User-Agent，以及交卷 IP；开始与交卷 IP 不一致时明确标记，供分享者辅助核查。

### 6.4 管理员全平台视图

“系统管理”下增加“考试管理”，或在考试管理页面中为管理员增加清晰隔离的“全部考试”视图。管理员视图至少支持：

- 查看所有用户创建的考试活动。
- 按分享者、工作空间、书籍、状态和时间范围筛选。
- 查看活动统计和参与者答题详情。
- 追踪关联的 AI 评分 Token 用量。
- 查看行为写入审计日志。

第一版建议管理员只读查看其他用户的活动，不直接修改、恢复或停止普通用户的分享；平台治理能力后续单独增加并记录操作原因。

### 6.5 公开考试页面

公开考试页面使用独立的简洁布局，不展示登录后系统的侧栏和系统管理入口。页面至少包括：

- 考试活动名称、书名、题目数量、题目构成、预计用时和分享者名称。
- 当前平台/微信身份，或匿名答题名称输入框；启用微信登录时提供微信授权按钮。
- 开始答题、题目导航、答题进度、交卷和提前交卷。
- 无效、停止或过期链接的明确状态页。
- 评分中、评分失败和已完成结果状态。

## 7. 答案、原文和隐私边界

### 7.1 交卷前

公开参与者在交卷前不能从页面或接口获得：

- 正确答案。
- 问答题参考答案和评分要点。
- 题目解析。
- PDF 文件名、页码、原文摘录和关键句高亮。

这既用于避免泄题，也避免通过公开链接传播用户上传的受版权保护 PDF 内容。

### 7.2 交卷后

第一版建议参与者可以查看：

- 总分、满分和得分率。
- 自己的答案和逐题得分。
- 客观题正确答案。
- 问答题参考答案、评分反馈和普通解析。

公开结果页仍不展示 PDF 文件名、页码和原文摘录。分享者和管理员在有权限的管理页面中可以查看完整评分依据和来源信息。

参与者的公开结果页展示其个人薄弱知识点和建议深入方向，但不展示后台采集的 IP、终端类型或 User-Agent。

### 7.3 数据可见范围

- 分享者只能查看自己创建的考试及其参与者数据。
- 登录参与者只能通过公开考试流程访问自己的答题记录，不能查看其他参与者。
- 匿名参与者只能凭该答题记录对应的匿名访问凭据访问自己的答卷。
- 微信参与者只能凭有效微信会话访问绑定到该微信身份的答卷。
- 管理员可以查看全平台数据，但跨用户访问必须审计。
- 普通用户即使知道活动 ID、答题记录 ID 或其他用户 ID，也不能通过管理接口越权读取数据。

## 8. 数据模型建议

### 8.1 `ExamShare`（考试活动）

建议包含：

- 活动 ID、分享代码和活动名称。
- 原试卷 ID、书籍 ID、分享者用户 ID、工作空间 ID。
- 只读试卷快照及快照版本。
- 状态、创建时间、停止时间和可选过期时间。
- 最近答题时间及必要的统计缓存字段。

### 8.2 `ExamAttempt`（答题记录）

建议包含：

- 答题记录 ID、考试活动 ID。
- 参与者类型、可选登录用户 ID、答题名称快照。
- 可选微信用户 ID 和参与者头像快照；微信用户表独立于平台账号，不获得书架或后台权限。
- 匿名访问凭据哈希。
- 状态、开始时间、提交时间、完成时间和用时。
- 得分、满分、得分率和评分失败原因。
- 开始答题终端类型、浏览器 User-Agent、开始 IP 和提交 IP；历史未采集字段允许为空。
- 创建请求的必要防重复和辅助核查信息，但不依赖 IP 地址判断唯一身份或直接判定作弊。

### 8.3 `ExamAnswer`（逐题答案）

建议包含：

- 答题记录 ID、快照题目 ID。
- 用户答案、是否已作答、得分和满分。
- AI 评分反馈、命中要点、缺失要点和评分状态。

所有考试活动和答题数据都必须保留 `owner_user_id`、`workspace_id` 或可等价追溯的归属关系，以支持工作空间隔离和管理员统计。

## 11. 非功能与安全要求

- 正式公网开放前必须配置 HTTPS，生产 Cookie 必须启用 `Secure`。
- 公开接口需要按分享链接、IP 和时间窗口限流，防止批量枚举、恶意提交和 AI 评分资源滥用。
- 需要限制单个考试活动的并发答题数、每日提交数和 AI 评分预算；具体配额作为后续平台设置预留。
- 分享代码和匿名访问凭据不得写入普通业务日志，服务端数据库只保存匿名凭据哈希。
- 微信 AppSecret 不得返回前端；OAuth 状态只能消费一次并绑定发起浏览器，微信会话使用 `HttpOnly`、`SameSite=Lax` Cookie，生产环境同时启用 `Secure`。
- 微信正式联调必须具备审核通过的网站应用、与平台一致的授权回调域和 HTTPS；当前 HTTP 环境不得启用生产微信登录。
- 公开接口返回字段使用独立响应模型，不能直接复用包含正确答案和 PDF 来源的内部试卷模型。
- 创建、停止、恢复分享和管理员跨用户查看均需要审计。
- 答题终端、User-Agent 和 IP 只允许分享者及管理员通过管理接口读取，公开参与接口必须隐藏；IP 变化仅作为风险提示，不能单独作为作弊结论。
- 所有时间按后端 UTC 保存，前端按北京时间 `YYYY-MM-DD HH:MM:SS` 展示。
- 第一版可以在现有 SQLite 和进程内后台任务环境中开发验证；正式多人公网运行前仍必须迁移 PostgreSQL、Redis Worker 和对象存储。

## 12. 第一版验收标准

1. 用户可以从自己的一套已完成试卷创建考试活动并复制分享链接。
2. 未登录参与者填写答题名称后可以开始、继续、提交并查看自己的结果。
3. 登录参与者打开同一链接时自动使用当前账号，不显示匿名名称输入框。
4. 客观题正确评分，未作答题按 0 分；问答题异步评分，失败后答案不丢失且可重试。
5. 交卷前的公开接口不返回答案、解析、评分要点和 PDF 来源内容。
6. 分享者可以在考试管理中查看链接、活动状态、统计指标和每位参与者的答题详情。
7. 分享者停止活动后不能开始新的答题，已有答卷仍可提交和查看。
8. 普通用户不能读取或管理其他用户创建的考试，即使已知资源 ID。
9. 管理员可以在后台查看任意用户的考试和答题情况，且访问行为有审计记录。
10. 原试卷删除后活动停止，但已有答题记录、成绩和快照仍可查看。
11. 匿名答题记录不能只凭答题记录 ID 访问，必须校验对应的随机访问凭据。
12. 公开考试和管理页面在桌面网页端完成完整流程，并具备基础移动端可用性。
13. 考试详情按参与者展示已完成答卷的 0-100 分柱状图，未完成评分的记录不混入成绩统计。
14. 每份完成答卷都能输出薄弱知识点及建议深入方向，参与者本人、分享者和管理员均可在各自授权页面查看。
15. 分享者和管理员可以查看答题终端、开始/提交 IP 及 IP 变化提示，参与者公开结果不能读取这些后台字段。
16. 分享者和管理员可以在单场考试中按参与者导出答题报告长图；参与者完成评分后可以在结果页一键保存自己的答题报告长图。报告完整包含成绩、逐题作答、正确或参考答案、评分反馈、薄弱知识点和深入学习方向。
17. 管理端导出报告可以包含终端和 IP 风控记录；参与者自行保存的报告不能包含终端、IP、User-Agent、PDF 文件名、页码或原文摘录。
18. 管理员可以保存脱敏的微信网站应用配置，并选择是否要求公开考试必须微信认证。
19. 微信参与者使用昵称和头像答题，同一微信账号再次打开链接时可以继续或查看原答卷；管理接口不泄露 `openid/unionid`。
20. OAuth 状态过期、重复使用或浏览器不匹配时授权失败，不能创建微信会话或答卷。

## 13. 本期不做

- 公开考试广场、公开题库搜索、社区分享和排行榜。
- 邮件、短信、二维码或社交平台自动分发。
- 实名认证、组织班级、监考、防切屏和严格防作弊。
- 匿名答题记录跨设备找回。
- 手工批改、教师评语和成绩申诉流程。
- 批量 CSV/Excel 成绩导出、证书、及格线和排名；第一版仅支持按参与者导出 PNG 答题报告。
- 考试开始时间、预约发布、访问密码和指定账号名单。
- 参与者自行重新答题或无限次提交。
- 将外部考试成绩合并到个人复习历史。

## 14. 已确认产品决策

第一版按以下方案实现：

1. **活动关系**：一个分享链接允许多人答题；同一套试卷可以创建多个独立链接。
2. **提交次数**：登录用户每个链接默认只能提交一次；匿名用户按浏览器凭据做弱限制，不承诺严格防重复。
3. **结果展示**：提交后参与者立即看到分数、正确答案、参考答案和解析，但始终不展示 PDF 文件名、页码和原文摘录。
4. **有效期**：链接默认长期有效，分享者可在创建时或考试管理中设置、修改、清除截止时间；到期禁止未提交答卷继续作答，但保留已提交历史结果。
5. **问答评分**：提交后进入异步评分，评分失败时保留答案，并允许分享者或管理员重新评分。
6. **原试卷删除**：自动停止对应活动，但保留试卷快照和历史答题结果。
7. **管理员权限**：第一版只读查看其他用户的考试和答题结果，不代替普通用户停止或恢复分享。
8. **停止后的在途答题**：活动停止后不允许新参与者开始，已经开始的参与者仍可完成并提交。
9. **报告导出**：采用浏览器端即时生成 PNG 长图，不把导出文件上传或持久化到服务器；管理页面按参与者导出时包含授权可见的风控摘要，公开结果页只生成参与者可见字段。
10. **微信身份**：微信用户是独立的公开考试参与者身份，不自动创建平台账号；可按平台策略强制使用，但只能证明微信账号控制权，不能表述为实名认证。
