# 可信台词资料与角色专题出题设计

实施状态（2026-09-03）：可信资料底座、全部计划格式解析、台词校对、结构化导入、专题出题、来源校验、事实级题目去重、单题重出和考试快照兼容已经完成；自动角色推断和专题运营统计留在后续阶段。

## 1. 目标

在现有书籍、电影和电视剧资源之上增加一条可信台词出题链路：用户上传自己确认可信的字幕、剧本或台词表，系统完成解析和必要的角色归属校对，再基于这些资料生成经典台词或指定角色专题试卷。

这项能力解决两个问题：

- 让电影和电视剧不再只能依赖模型记忆出题。
- 让“谁说了这句话、发生在什么场景、体现了什么人物特征”成为可追溯的专题测试。

## 2. 核心产品决策

### 2.1 专题不是新题型

系统继续使用单选题、多选题和问答题。`经典台词`、`角色专题`属于出题主题，负责约束题目内容，不参与评分规则。

第一版主题：

| 主题 | 适用资源 | 说明 |
| --- | --- | --- |
| `general` 综合内容 | 全部 | 综合已解析 PDF 与已确认台词；两类资料都没有时使用模型知识兜底 |
| `classic_quotes` 经典台词 | 全部 | 从可信资料中选择台词，考察说话人、场景或含义 |
| `character` 角色专题 | 小说、电影、电视剧 | 围绕一个或多个已确认角色生成题目 |

### 2.2 精确台词禁止模型知识兜底

包含逐字台词、说话人或具体场景的题目，只能来自用户上传的可信资料。模型真实性检查通过，只代表模型对作品有总体知识，不代表它能准确复述台词。

- `classic_quotes` 必须选择至少一份已就绪的可信资料。
- `character` 如果包含台词题，也必须使用可信资料。
- 没有可信资料时仍可生成一般角色理解题，但不能声称某句原话、具体集数或时间点准确。

### 2.3 模型负责组织题目，后端负责守住事实

模型可以选择考察角度、生成干扰项和解释，但后端必须验证台词、角色归属和来源定位。任何一项无法验证，本次题目生成失败，不保存半成品。

### 2.4 沿用现有考试能力

专题试卷生成后仍然进入现有试卷编辑、单题重出、答题、评分、考试分享和版本快照流程。已开始或已完成的答卷继续冻结各自的题目快照。

现有后台预生成继续使用 `general` 综合内容主题，不自动生成经典台词或角色专题；如果资源已有已确认台词，综合出题会将其作为可信候选来源。

## 3. 用户流程

整体流程：

```text
上传可信资料
    |
    v
异步解析为片段、时间、集数和角色信息
    |
    v
角色归属是否可靠？ ---- 否 ----> 人工校对：确认、修改或排除
    |                                  |
    是                                 |
    |                                  |
    +------------------<---------------+
    |
    v
形成可信台词池
    |
    v
选择专题、角色、资料和考察角度
    |
    v
模型逐题生成
    |
    v
后端校验台词、角色和来源
    |                         |
    | 通过                    | 不通过
    v                         v
保存专题试卷              任务失败并说明原因
    |
    v
复用编辑、单题重出、复习、考试分享和版本快照
```

### 3.1 上传可信资料

入口位于资源详情页的“可信资料”区域。电影和电视剧不再显示“不能上传 PDF”，而是根据资料类型提供上传入口。

首期支持：

| 资料类型 | 文件格式 | 解析结果 | 角色可信度 |
| --- | --- | --- | --- |
| 剧本或整理稿 | PDF、TXT | 按页、段落或场景切分 | 从明确的角色标记读取；不明确时待校对 |
| 字幕 | SRT、VTT、ASS | 按集数、时间和字幕条目切分 | 文件未包含说话人时待校对 |
| 结构化台词表 | CSV、XLSX | 每行形成一条台词记录 | `角色 + 台词`完整且校验通过时直接可用 |

结构化台词表必填列：

- `台词`
- `角色`

可选列：

- `季`
- `集`
- `开始时间`
- `结束时间`
- `场景`
- `上下文`
- `版本说明`

系统提供可下载的 CSV 模板。多文件上传按文件分别展示处理结果；某个文件失败不能覆盖已经成功的文件。

### 3.2 资料处理状态

资料状态统一为：

```text
等待解析 -> 解析中 -> 待校对 -> 可用于出题
                    \-> 解析失败 -> 重新解析或删除
```

- 结构化台词表通过字段校验后可直接进入“可用于出题”。
- 字幕和自由文本没有可靠说话人时进入“待校对”。
- 用户可以在资源详情页离开，后台继续处理。
- 服务重启后恢复等待中或解析中的任务，沿用现有持久化后台任务策略。

### 3.3 台词校对

“待校对”资料显示“校对台词”入口。校对页采用高密度列表，不使用逐条弹窗。

每行展示：

- 台词正文
- 当前角色
- 季、集、时间或页码
- 前后文
- 角色来源：资料自带、模型推断、人工确认
- 可用于出题状态

支持按状态、角色和资料筛选，支持搜索台词，支持勾选后批量确认或排除。修改角色后需要显式保存；离开存在未保存内容的页面时给出提醒。

模型推断的角色默认不能用于“谁说了这句话”类型的题，必须经过人工确认。没有角色的台词仍可用于场景理解题，但不能生成角色归属题。

### 3.4 生成专题试卷

现有生成试卷页增加“出题主题”分段选择：

- 综合内容
- 经典台词
- 角色专题

选择“经典台词”后显示：

- 可信资料，多选，默认选择全部已就绪资料
- 角色，可选，默认全部角色
- 考察角度，多选：说话人、对话场景、台词含义
- 题型和题量，复用现有控件

选择“角色专题”后显示：

- 角色，必选，可选择一个或多个已确认角色
- 是否包含经典台词
- 可信资料，仅在包含经典台词时必选
- 考察角度：人物关系、关键行为、表达立场、经典台词

当可用台词数量不足时，主题选项保留但禁用生成按钮，并在控件附近说明还差多少条以及“上传资料”或“校对台词”的解锁路径。

### 3.5 查看与编辑

试卷概览和编辑页展示主题与角色范围，例如：

```text
专题：经典台词
范围：吴站长
来源：潜伏第 1-30 集校对字幕
```

题目编辑与单题重出继续复用现有入口。单题重出必须继承主题、角色、资料集合和考察角度，且不能重复使用本试卷已占用的台词。

## 4. 题目生成规则

### 4.1 题目子类型

在现有 `question_type` 之外新增 `question_subtype`，用于约束生成、重出和统计：

| 子类型 | 常用题型 | 必要依据 |
| --- | --- | --- |
| `quote_speaker` 台词说话人 | 单选、多选 | 已确认角色归属 |
| `quote_context` 台词场景 | 单选、问答 | 场景或上下文；集数和时间仅用于来源定位 |
| `quote_meaning` 台词含义 | 单选、问答 | 台词及上下文 |
| `character_relation` 人物关系 | 单选、多选、问答 | 可信资料中的关系或对话证据 |
| `character_trait` 人物特征 | 单选、问答 | 多条行为或台词证据 |

### 4.2 确定性校验

后端在保存题目之前执行：

1. 题目引用的 `quote_entry_id` 必须属于当前用户工作空间和当前资源。
2. 台词必须与来源片段归一化后精确匹配；允许合并连续字幕条目，但必须记录全部片段 ID。
3. `quote_speaker` 的正确答案必须来自人工确认或结构化资料明确提供的角色。
4. 场景题可以使用资料中的集数、时间、页码或上下文作为来源定位，但题目只考察语境、人物处境和事件背景，不要求考生回忆精确集数、时间点或出处位置。
5. 干扰角色只能来自当前作品的已确认角色集合，不能虚构角色。
6. 一套试卷不能重复使用同一条台词，也不能重复考察同一个事实；事实指纹由主体、关系、情节范围和答案事实值组成，题干换写不视为新题。
7. 模型不能返回未提供的资料 ID、角色、集数、页码或时间点；也不能把这些精确定位信息设计成题目答案。
8. 展示的台词截取长度采用系统配置，默认只保留完成题意所需的短片段。

### 4.3 模型输出扩展

模型生成题目时增加以下字段：

```json
{
  "question_subtype": "quote_speaker",
  "quote_entry_ids": ["quote-id"],
  "source_segment_ids": ["segment-id"]
}
```

这些字段由后端交叉校验后再保存，不能只信任模型返回值。`theme_scope` 不要求模型回传，而是由后端从出题任务的 `generation_theme` 和 `theme_config` 直接写入试卷与考试快照。

## 5. 数据设计

现有 `PdfDocument` 和 `ContentChunk` 强绑定 PDF。新增功能采用通用资料模型，同时保留旧表和旧接口兼容已有数据。

### 5.1 `resource_materials`

| 字段 | 说明 |
| --- | --- |
| `id` | 资料 ID |
| `book_id` | 沿用当前资源外键命名 |
| `material_type` | `book_text / script / subtitle / quote_sheet` |
| `file_format` | `pdf / txt / srt / vtt / ass / csv / xlsx` |
| `file_name`、`file_path`、`file_size` | 文件信息 |
| `file_hash` | 去重和变更检测 |
| `season_number`、`episode_label` | 可选范围信息 |
| `version_label` | 剪辑版、字幕版本等说明 |
| `parse_status` | `pending / processing / needs_review / completed / failed` |
| `error_message` | 可操作的失败原因 |
| `segment_count`、`quote_count` | 处理统计 |
| `created_by_user_id` | 上传人 |

### 5.2 `material_segments`

| 字段 | 说明 |
| --- | --- |
| `id`、`book_id`、`material_id` | 归属关系 |

| `start_ms`、`end_ms` | 字幕时间，可空 |

### 5.3 `quote_entries`

| 字段 | 说明 |

| `enabled_for_generation` | 是否允许出题 |

### 5.4 现有表扩展

`QuizGenerationTask` 和 `Quiz` 增加：

- `generation_theme`
- `theme_config`，保存角色、资料集合和考察角度

`Question` 增加：

- `question_subtype`
- `quote_entry_ids`
- `source_segment_ids`

来源模式按兼容方式扩展为：

- 旧数据继续保留 `pdf`
- 新上传资料使用 `material`
- 没有 PDF 和已确认台词资料时使用 `model_knowledge`

前端把 `pdf` 和 `material` 都显示为“可信资料”，但保留具体文件格式和定位方式。后续可以再迁移旧 PDF 到通用资料表，不要求第一阶段重写全部历史数据。

## 6. API 设计

### 6.1 资料管理

```text
POST   /api/books/{book_id}/materials
GET    /api/books/{book_id}/materials
GET    /api/books/{book_id}/materials/{material_id}
POST   /api/books/{book_id}/materials/{material_id}/reparse
DELETE /api/books/{book_id}/materials/{material_id}
GET    /api/material-templates/quote-sheet.csv
```

上传接口使用 `multipart/form-data`，文件以流式方式写入本地存储，完成基本文件签名、扩展名、编码和工作空间校验后创建异步解析任务。

### 6.2 台词校对

```text
GET    /api/books/{book_id}/quotes
PATCH  /api/books/{book_id}/quotes/{quote_id}
POST   /api/books/{book_id}/quotes/bulk-confirm
POST   /api/books/{book_id}/quotes/bulk-reject
```

列表接口支持 `material_id`、`speaker`、`review_status`、`search` 和分页。批量接口必须再次校验所有台词属于当前工作空间和资源。

### 6.3 出题请求扩展

`POST /api/books/{book_id}/quizzes` 增加：

```json
{
  "generation_theme": "classic_quotes",
  "theme_config": {
    "material_ids": ["material-id"],
    "character_names": ["吴站长"],
    "question_subtypes": ["quote_speaker", "quote_context", "quote_meaning"]
  }
}
```

后端根据所选题量预检可用台词数量。预检只决定是否可以启动任务，模型生成后的逐题校验仍然必须执行。

## 7. 后台处理流程

1. 流式保存文件并计算哈希；同一资源下重复文件提示用户，不重复解析。
2. 按文件格式解析为 `material_segments`。
3. 识别明确写在资料中的角色和定位信息。
4. 对未标角色的内容，可选择调用模型生成候选角色，但状态保持“待校对”。
5. 生成和去重 `quote_entries`。
6. 只有符合可信规则的台词进入出题候选池。
7. 出题时按主题、角色、资料和历史使用记录检索候选台词。
8. 模型逐题生成，后端逐题校验；整套完成后一次性保存试卷。

处理进度按阶段记录：保存文件、解析内容、识别定位、整理台词、等待校对、可用于出题。普通成功状态不常驻占用页面，只在资料列表中显示紧凑状态。

## 8. 删除与历史行为

- 删除资料会删除原始文件、片段和台词候选。
- 删除前明确提示：以后不能再基于该资料出题或重出题。
- 已经生成的试卷和考试快照继续保留，因为题目已经保存必要的来源快照。
- 如果用户要求彻底删除台词内容，需要继续删除关联试卷和考试；这属于单独的高影响清理动作，不和普通资料删除混在一起。
- 资料被删除后，依赖它的题目仍可人工编辑，但不能自动重出。

## 9. 权限、安全与内容边界

- 资料、片段和台词全部继承当前资源的工作空间隔离。
- 普通用户只能管理自己的资料；管理员跨用户查看沿用现有只读管理边界。
- 原始资料、片段和台词不得出现在公开考试接口中。
- 公开考试仍按当前规则隐藏来源证据；题目本身需要的短台词属于试卷快照内容。
- 文件名必须净化，服务端生成存储路径，不能使用用户输入路径。
- 校验文件签名、扩展名、编码和解析器资源消耗，解析失败必须给出下一步。
- 上传文本仍视为不可信输入；提示词必须继续声明不能执行资料中的指令。
- 同一台词的公开展示长度和批量分享范围采用平台配置，避免把专题考试变成原始资料分发渠道。

## 10. 页面与组件决策

### 10.1 资源详情页

“可信资料”使用全宽列表和分隔线，不增加嵌套卡片。每个文件一行展示类型、范围、台词数量、状态和操作。主动作使用上传图标加“上传资料”。

### 10.2 上传交互

文件选择和少量元数据使用对话框；上传开始后立即回到资料列表，由行内进度展示每个文件状态。失败项保留并提供“重新解析”和“删除”，成功项不因其他文件失败而回滚。

### 10.3 校对页

使用可筛选的列表或表格、复选框和批量动作。角色是可搜索的选择器，不用任意自由输入作为默认方式；需要新增角色时提供明确命令。确认和排除使用不同动词，不用含糊的“处理”。

### 10.4 生成页

主题使用分段控件，角色和资料使用选择菜单，考察角度使用复选框。暂时不可用的主题保留位置并解释原因和解锁路径，不直接隐藏。

### 10.5 状态完整性

必须覆盖首次无资料、解析中、部分文件成功、待校对、全部可用、解析失败、权限不足、资料被删除、出题候选不足和模型返回不合规等状态。

## 11. 测试设计

### 11.1 后端

- PDF、TXT、SRT、VTT、ASS、CSV 和 XLSX 解析夹具。
- 编码错误、空文件、伪装扩展名、重复文件和畸形字幕。
- 工作空间隔离和管理员只读边界。
- 台词归一化匹配、连续字幕合并、角色确认和跨资料去重。
- 没有确认角色时拒绝 `quote_speaker`。
- 模型伪造台词、角色、集数、时间或资料 ID 时拒绝保存。
- 单题重出继承主题且不重复台词。
- 删除资料后历史试卷保留、自动重出被拒绝。

### 11.2 前端

- 多文件上传的独立成功与失败状态。
- 待校对筛选、修改角色、批量确认和未保存离开提醒。
- 经典台词主题的资料、角色和考察角度联动。
- 候选不足时按钮状态、原因和跳转路径。
- 出题进度、失败重试和完成后进入现有试卷流程。

### 11.3 回归

- 旧 PDF 出题、模型知识出题、预生成和人工编辑不受影响。
- 复习评分、考试分享、版本快照和公开字段隔离保持现有行为。

## 12. 分阶段交付

### 阶段一：通用可信资料底座

- 新增资料、片段和台词表。
- 支持 PDF、TXT、SRT、VTT、ASS 上传和异步解析。
- 资源详情页展示资料状态。
- 旧 PDF 链路保持兼容。

交付标准：电影或电视剧可以上传字幕或剧本，系统能稳定形成可定位的片段，单文件失败不影响其他文件。

### 阶段二：台词校对与结构化导入

- 支持 CSV、XLSX 台词表和模板下载。
- 建立台词候选、角色来源和人工确认流程。
- 支持筛选、批量确认、排除和重新解析。

交付标准：用户能明确知道哪些台词可用于角色归属题，并能修正模型推断结果。

### 阶段三：专题出题

- 增加主题、角色和考察角度配置。
- 扩展提示词、模型输出和确定性校验。
- 支持专题单题重出、试卷展示和历史去重。

交付标准：任何逐字台词题都能追溯到上传资料；伪造台词、角色和定位信息无法入库。

### 阶段四：稳定性与运营验证

- 完成解析任务恢复、用量审计和批量资料管理。
- 统计专题试卷完成率、分享率、题目纠错率和台词争议率。
- 根据真实使用情况决定是否增加自动角色识别和更多题目子类型。

## 13. 本期不做

- 自动从互联网抓取台词或字幕。
- 把模型记忆当作精确台词来源。
- 未经用户确认自动发布台词题库。
- 面向全站共享的公共台词库。
- 自动判定上传资料的版权授权状态。
- 自动为后台预生成任务选择经典台词或角色专题。
- 在第一阶段重写现有答题、评分和考试快照系统。

## 14. 验收结论

功能上线前必须同时满足：

1. 用户能够为电影和电视剧上传可信资料，并看到逐文件处理结果。
2. 系统能区分资料自带角色、模型推断角色和人工确认角色。
3. 未确认的角色归属不能进入说话人题。
4. 所有逐字台词都能定位到上传资料。
5. 专题范围会写入出题任务、试卷和考试快照。
6. 单题重出不会越过专题、角色和资料边界。
7. 原始资料不会通过公开考试接口泄露。
8. 旧试卷、旧 PDF 和模型知识模式保持兼容。
