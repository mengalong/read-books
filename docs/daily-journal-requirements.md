# 日常记录与每日整理功能设计 v0.1

更新日期：2026-09-07

## 1. 产品定位

日常记录是“回卷”中的独立业务模块，与阅读复习共享账号、个人工作空间、模型配置、后台任务和 Token 统计底座，但不依赖书籍、试卷或复习任务模型。

核心闭环为：

```text
随时快速记录 -> 按日保留原始时间线 -> 模型生成日记草稿
              -> 提取待办/灵感/想读/想看 -> 长期清单持续追踪
```

原始记录是事实来源。日记和归集项都是可编辑的派生产物，模型不得覆盖或改写原始记录。

## 2. 当前 MVP 范围

### 2.1 快速记录

支持五种记录类型，提交后的原始记录仍然可以修改内容、分类、日期和标签：

- `note`：普通记录，允许模型在每日整理时推断其中是否包含可归集项目。
- `todo`：用户明确标记的待办，保存记录时直接进入开放任务清单。
- `idea`：用户明确标记的灵感，直接进入灵感收件箱。
- `want_read`：用户明确标记的想读内容，直接进入想读收件箱。
- `want_watch`：用户明确标记的想看内容，直接进入想看收件箱。

每条记录保存原始文本、记录时间、北京时间所属日期、用户类型、标签、创建用户和工作空间。编辑记录后会使对应日期重新进入“尚未整理”；从显式项目分类改回普通记录时，原先直接创建的项目会标记为 `dismissed`，避免继续显示为有效项目。删除原始记录不会自动删除已经归集的长期项目，避免误删已经进入执行阶段的任务。

### 2.2 每日整理

用户可以对任意日期手动发起整理。接口立即返回，后台线程执行以下步骤：

1. 按记录时间读取当天全部原始记录。
2. 使用当前有效模型配置生成日记草稿、当天重点和结构化项目。
3. 校验模型返回的项目类型、来源记录 ID、置信度和日期。
4. 按项目类型和标准化标题合并重复项目，并追加来源记录。
5. 保存日记草稿、摘要、归集项目和任务状态。

服务重启后会恢复状态为 `processing` 的每日整理任务。Mock 模式使用确定性规则生成可联调的日记和归集结果；真实模式调用 OpenAI 兼容接口。

### 2.3 显式分类与模型推断

- 用户明确标记的待办、灵感、想读和想看项目直接进入对应清单。
- 模型从普通记录推断出的项目进入 `needs_review`，必须由用户确认后才进入长期收件箱。
- 项目始终保存 `source_capture_ids`，用户可以追溯其原始记录。
- 相同类型、标准化标题相同的项目进行合并，不重复创建。

### 2.4 日记草稿

- 日记只根据当天原始记录生成，不得补写用户没有记录的事实。
- 日记支持自然纪实、鲁迅式冷峻讽刺、胡适式平实自省和清简随笔等写作风格；风格只借鉴高层次语言特征，不复制具体作品句子。
- 输出固定为可直接复制的 Markdown，包含标题、今日概览、日记、今日重点和按类型归集的项目段落；模型需要提炼事件、感受、转折和思考，不得逐条机械复述原始记录。
- 草稿允许人工编辑并自动保存，页面显示最近一次自动保存时间；不再提供单独的“保存草稿”按钮。
- 草稿支持“编辑 / 预览”切换，复制操作使用文本框右上角图标，成功后显示明确反馈。
- 重新整理会生成新草稿；当前 MVP 尚未保存历史草稿版本，确认前应由用户检查。

### 2.5 长期清单

统一使用 `journal_items` 保存四类长期项目：

| 类型 | 初始状态 | 可用状态 |
| --- | --- | --- |
| 待办 | `open` | `needs_review`、`open`、`done`、`cancelled`、`dismissed` |
| 灵感 | `inbox` | `needs_review`、`inbox`、`archived`、`dismissed` |
| 想读 | `inbox` | `needs_review`、`inbox`、`added`、`completed`、`dismissed` |
| 想看 | `inbox` | `needs_review`、`inbox`、`added`、`completed`、`dismissed` |

想读和想看项目当前不会自动创建正式内容库资源；`added` 在界面显示为“已采纳”，只表示用户已经推进该候选。后续应增加明确的“加入内容库”操作，并执行标题确认和重复资源检查。

项目对外使用统一决策状态：`pending`（待确认）、`confirmed`（已确认）、`completed`（已完成，仅待办）、`cancelled`（已取消）和 `deleted`（已删除）。旧的 `status` 字段继续用于兼容历史客户端，但新页面和整理任务以 `review_status` 为准。删除项目使用软删除，后续重复整理会继承删除决定。

## 3. 页面与接口

页面：

- `/journal`：日期切换、快速记录、当天时间线、日记草稿和当天归集项。
- `/journal/items`：统一表格展示待办、灵感、想读和想看项目，按类型、标题/媒体名称、原因/说明、提及时间、状态和操作列组织；支持按类型筛选、编辑、确认/取消和删除。

接口：

- `GET /api/journal/days/{local_date}`：读取或初始化某天数据。
- `POST /api/journal/captures`：创建快速记录。
- `PATCH /api/journal/captures/{capture_id}`：编辑当前工作空间的原始记录内容、类型、日期和标签。
- `DELETE /api/journal/captures/{capture_id}`：删除当前工作空间的原始记录。
- `POST /api/journal/days/{local_date}/organize`：按指定写作风格启动每日整理。
- `PATCH /api/journal/days/{local_date}`：保存或确认日记草稿。
- `GET /api/journal/days/{local_date}/versions`：读取日记历史版本。
- `POST /api/journal/days/{local_date}/versions/{version_number}/restore`：恢复指定日记版本。
- `GET /api/journal/summaries?period=week|month`：读取周期回顾的每日汇总。
- `GET /api/journal/items`：按类型和状态读取长期项目。
- `PATCH /api/journal/items/{item_id}`：编辑分类、标题、说明、截止日期或状态。
- `DELETE /api/journal/items/{item_id}`：删除归集项目，不删除来源记录。

当天页面的归集卡片支持直接修改分类。模型推断项可以点击“打回”，项目会进入 `dismissed` 状态并保留来源记录；用户仍可以在卡片或长期清单中恢复、改成其他类型或删除。

所有接口依赖登录完成、密码已修改的身份，并按当前个人工作空间过滤对象。

## 4. 数据模型

### `journal_captures`

保存不可被模型覆盖的原始输入，包括 `workspace_id`、`created_by_user_id`、`content`、`capture_type`、`local_date`、`captured_at` 和 `tags`。

### `journal_days`

按 `workspace_id + local_date` 唯一，保存日记草稿、写作风格、摘要、整理任务 ID、任务状态、错误、整理时间和确认时间。

### `journal_items`

保存跨日期持续存在的任务、灵感和媒体候选，包括类型、标题、说明、状态、来源记录 ID、模型置信度、截止日期和扩展元数据。想读/想看项目的扩展元数据包含 `media_title`、`reason`、`mentioned_at`、可选的 `creator` 和 `media_kind`，清单页提供结构化表格视图。

## 5. 隐私与模型边界

日记比阅读资料更敏感，模型调用遵循以下规则：

- 只有用户主动点击整理时，才把当天记录发送给当前配置的模型服务。
- 日常整理会记录 Token 数量、模型名称、耗时和成败，但不把日记 Prompt 或模型原始回复复制到通用调试日志。
- 模型不能做心理诊断、人生价值结论或未授权的长期画像。
- 普通业务接口只能访问当前工作空间；已知其他工作空间对象 ID 也必须返回不可访问。
- 后续增加导出、彻底删除、加密备份和数据保留期限前，不把日记模块视为公网多用户生产就绪。

## 6. 验收标准

- 用户可以在当天页面用五种类型保存快速记录。
- 明确分类的项目保存后立即出现在长期清单。
- 普通记录经过每日整理后，模型推断项目以待确认状态出现。
- 每日整理异步执行，页面可以轮询看到完成或失败结果。
- 日记草稿可以编辑、自动保存、查看历史版本和恢复，原始记录不被覆盖。
- 已提交原始记录可以编辑内容、分类、日期和标签。
- 日记草稿以结构化 Markdown 输出，并支持选择写作风格和一键复制。
- 归集项目保留来源记录 ID，并能按类型查询、编辑分类、更新状态和删除。
- 当天归集卡片支持直接打回和修改类型，打回不会删除原始记录。
- 所有日常数据按工作空间隔离。
- 可以关闭某一天的模型发送授权；真实模型整理在未授权时会拒绝发送原始记录。
- 周期回顾按周/月展示记录数、归集数、完成待办和自评心情。
- Mock 模式、真实模型模式和模型调用隐私策略均有明确边界。

## 7. 后续范围

- 自动定时整理和按用户配置时区确定每日边界。
- 日记草稿版本历史、局部重新生成和排除指定原始记录。
- 待办截止时间自然语言解析、提醒、延期和重复任务。
- 想读/想看候选经确认后转换为内容库资源。
- 周报、月报、灵感主题聚合、情绪和精力的用户自评趋势。
- 导出、彻底删除、加密备份和独立的日记数据保留策略。
